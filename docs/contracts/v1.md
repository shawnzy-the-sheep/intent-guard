# UX Contract v1

Required top-level fields: `version: 1`, safe unique `id`, `page.route`, `user.role`, `goal.primary`, `entities`, `actions`, and a non-empty `intents` array. Each entity/action requires priority (`primary`, `secondary`, `contextual`) and one or more CSS selectors. Selectors are unioned, not treated as a fallback chain.

Hierarchy intents reference two distinct entities. `dominant` expects subject dominance; `subordinate` expects relativeTo dominance. Ownership references an entity and expects `contextual`; action discoverability references an action and expects `immediate` or `discoverable`. The immediate variant includes top-two prominence; both variants check action availability.

IDs allow letters, digits, underscores and hyphens, starting with a letter/digit, at most 100 characters. Duplicate intent IDs and entity/action ID collisions are invalid. Unknown fields, schema versions and subject references are rejected before browser launch. Invalid browser CSS selectors fail collection rather than passing silently.

Use stable entity/action attributes instead of brittle CSS implementation selectors. Prefer one clearly scoped root per entity and explicit status roles/heading labels. Missing targets are INCONCLUSIVE, since evidence cannot prove a hidden or absent UI state from an unmatched selector.

Multiple roles can already be represented by separate contracts. Executing authenticated role fixtures, interactions and comparisons across states is later scope.
